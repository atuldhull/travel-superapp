>
> 1. **`apps/admin/`** — a Next.js scaffold _that does not exist yet_. `package.json` is a 3-line husk; `src/index.ts` is `export {};`. Verdict: **0%**.
> 2. **`apps/web/src/app/admin/`** — the _actual_ admin console. Six moderation queues, RBAC airtight, audit-logged. Verdict: **~65%**.
>
> Operator decision blocked on Z2 (see E1): **stay co-hosted on `apps/web` or extract into `apps/admin`?** This audit recommends co-hosting with an IP-allowlist for now; extract only if compliance / SOC2 demands a separate deploy.

## Verdict — **scaffold 0% · surface ~65%** (production-ready for incident response, ship-blocked for public ops)

The admin surface inside `apps/web/src/app/admin/` is functional: six moderation queues (scam reports, SOS, users + appeals, audit log, media takedown, compliance/retention) are wired to live API endpoints via generated `@app/sdk` hooks. RBAC is three-layer (API `@Roles('admin')` + `RolesGuard` → client `useAuthControllerMe` role check → audit log on every mutation). Every admin action writes an `AdminAuditLog` row (append-only). 17 admin-scoped + 2 compliance-scoped API routes are gated and consumed.

But three ship-blockers stop a real production rollout:

1. **No IP allowlist enforcement** — `ADMIN_IP_ALLOWLIST` is referenced in the schema but no `middleware.ts` reads it. Any logged-in admin reaches `/admin/*` from anywhere on the public internet. **E1.**
2. **Role promotion is manual** — no bootstrap script. A human runs Prisma Studio or raw SQL to set `User.role = 'admin'`. No oncall checklist. **E2.**
3. **Feature-flag editor + agent-KYC queue are missing UIs** — backends exist, UIs do not. **E3 + E5.**

The `apps/admin/` scaffold itself is empty by design (deferred per the package.json description: "Scaffold only — real code lands in [IV.18.1.14.b]"). The S-series should NOT inflate it for symmetry — co-hosting on web is the cheaper, simpler posture. Extract only if a compliance requirement forces it.

## API endpoints consumed

All gated by `@Roles('admin')` (or `@Roles('compliance', 'admin')`), all consumed via generated `@app/sdk` hooks. Bearer JWT carries the role claim; mismatch → 403 + audit row.

**Admin-scoped (17 routes):**

- `GET/POST/DELETE /api/v1/admin/places` (curate place catalog — backend ready, UI deferred)
- `GET /api/v1/admin/audit-logs` (list filterable + paginated)
- `GET /api/v1/admin/scam/moderation` (list pending)
- `POST /api/v1/admin/scam/:id/{verify,dismiss}` (verify → public scam map; dismiss → hard-delete)
- `GET /api/v1/admin/sos` (list filterable)
- `POST /api/v1/admin/sos/:id/resolve` (resolve + note)
- `GET /api/v1/admin/users` (search by displayName / role / deleted)
- `POST /api/v1/admin/users/:id/{ban,unban}` (logged with reason)
- `GET /api/v1/admin/users/appeals` (pending appeals queue)
- `GET/DELETE /api/v1/admin/media` (list filter by owner; hard-delete cascade)
- `GET /api/v1/admin/trips` (list — UI deferred)
- `PATCH /api/v1/admin/trips/:id/archive` + `DELETE /api/v1/admin/trips/:id` (logged)

**Compliance-scoped (2 routes):**

- `GET /api/v1/compliance/retention` — 16 indexed counts (users/trips/safety/notifications)
- `GET /api/v1/compliance/takedowns` — CSV-export-ready paginated audit rows

## RBAC / auth posture

**Three-layer defense:**

1. **API guard** (`apps/api/src/common/auth/roles.guard.ts` + `roles.decorator.ts`) — every admin controller class decorated `@Roles('admin')`; `JwtAuthGuard` → `RolesGuard`. Non-admin → 403 `ROLE_FORBIDDEN`; unauthenticated → 401 `UNAUTHENTICATED`. Source of truth: `req.user.role` claim.
2. **Client layout gate** (`apps/web/src/app/admin/layout.tsx`) — `useAuthControllerMe()` checks `me?.role === 'admin'`; non-admin renders a 403 panel. Defense-in-depth only; the API guard is what stops the bad request.
3. **Audit trail on every mutation** — `AdminAuditLogRepository.record({ actorId, action, targetType, targetId, context })` called from every use-case. Schema-enforced append-only (no `UPDATE` / `DELETE` HTTP surface; no edit API).

**Token storage** — admin layout uses the same `auth-store.ts` as the rest of `apps/web` (memory access token + httpOnly refresh cookie). CLAUDE.md rule 12 compliant.

**Role promotion** — manual today. No CLI script. Production bootstrap requires: developer with DB creds → `prisma studio` → set `User.role = 'admin'` → commit auditable PR via secrets workflow. **E2 builds the script.**

## Operator-owed

1. **Role-promotion script** — `scripts/admin/promote-user.sh` (reads `DATABASE_URL`, takes an email argument, sets `User.role = 'admin'`, writes a synthetic `AdminAuditLog` row attributing the promotion to the operator). Document the oncall checklist.
2. **IP allowlist middleware** — `apps/web/middleware.ts` reads `ADMIN_IP_ALLOWLIST` (comma-separated CIDRs) and returns 403 for non-allowlisted IPs on `/admin/*` routes. Update `.env.example` + docs.
3. **Vercel branch protection** — require 2 approvers for any deploy that touches `apps/web/src/app/admin/**` or `apps/api/src/modules/admin/**`.
4. **Admin oncall rotation** — document who can grant admin role + how to revoke; tie to incident response.
5. **GDPR export surface** — add `/admin/users/:id/gdpr-export` UI that calls existing `compliance` endpoints.
6. **Audit-log retention** — pair with [`docs/runbooks/db-partitioning.md`](../runbooks/db-partitioning.md) (yearly partitions for `AdminAuditLog` ≥7yr).

**Recommendation: do NOT extract `apps/admin/` into a separate Next.js app.** Keep co-hosting on `apps/web`. Add IP allowlist (E1) for blast-radius reduction; that's the same security posture as a separate app at 1/10 the operational complexity. Revisit only if SOC2 / customer compliance forces a hard separation.
